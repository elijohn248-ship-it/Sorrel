# Security and privacy invariants

Spec 1.0.0. Sources: AGENTS.md 2.2–2.4, CLAUDE.md ▸ Security invariants and ▸ Security behaviour, `Web.swift`, `Extensions.swift`, `MiniWindow.swift`, the updater. Each statement must hold in every edition. "Mac proof" names the existing check; "Chromium test" says how an edition's automated test proves it (BIRCH_* hooks, fresh `BIRCH_HOME`, local fixture server, in CI). These are rules, not fixtures, except where a fixture is named.

| # | Invariant (checkable) | Mac proof | Chromium test |
|---|---|---|---|
| S1 | Private windows use a non-persistent store: after a private window closes, no cookie, cache, local storage, history entry, downloads.json record or session-restore entry from it exists on disk. | `Engine.makeConfiguration(isPrivate:)` uses `.nonPersistent()`; SORREL_SECTEST, SORREL_WINDOWTEST | Off-the-record profile. Open a private window to a fixture that sets a cookie, localStorage and a cached image, download a file, close it, then list every file under `BIRCH_HOME` (including cache, crash-dump and GPU-cache folders) and search them for the fixture's marker strings: zero hits. history.json/state.json/downloads.json unchanged. |
| S2 | A link opened from a private window (⌘/Ctrl-click, middle-click) opens in another private window, never a normal tab. | SORREL_SECTEST "private cmd-click" | Hook clicks a link with the modifier in a private window; assert no normal-store tab exists and a new private window does. |
| S3 | No permission is granted without asking: camera, microphone, location, notifications. Location asks every time, "Don't Allow" is the default, nothing is remembered; camera/mic in private windows ask every time; requests from hidden tabs are refused. | `requestMediaCapturePermission`, `askForLocation`; SORREL_GEOTEST | Fixture page requests each permission; with no simulated answer, the hook logs a prompt was raised and the page got "denied". A hidden tab's request is denied without a prompt. Check the engine's permission store holds no grant afterwards. |
| S4 | The insecure-site Continue works only from Birch's own warning page, only while that warning is the page showing, and only for that host until quit. A web page that links/navigates to the continue address gets nothing. | `sorrel-insecure:` honoured only when `insecureOffers[webView]` matches the current URL; SORREL_SECTEST2 | Fixture page navigates to the continue address (and a stale warning is left behind); assert the http page did not load. Then the real warning's button works once. Implement the Continue as a native action from Birch's own page, not a URL web content can reach. |
| S5 | HTTPS-first: ordinary http:// main-frame GETs are tried over https first; local names, IPs and non-80 ports are never upgraded. | `fixtures/https-first.json`; SORREL_SECTEST | Run `https-first.json`; plus a fixture server with no https: the warning page appears with the http address. |
| S6 | The address box shows the committed URL's real host: only a leading `www.` is dropped; non-ASCII labels show as punycode; long hosts are truncated at the front; never a page-provided string (title, history.pushState text). | `fixtures/site.json` (address box cases) | Run `site.json`; load `https://xn--pple-43d.example`-style lookalikes from the fixture server and assert the displayed text equals the punycode host; screenshot a long host and check the tail is visible. |
| S7 | Ads and trackers are blocked by default; a broken site gets a per-site toggle (`blockingDisabledSites`), never a global off switch. Built-in lists always cover private windows. | Blocker.swift; SORREL_BLOCKTEST | Fixture page requests a known tracker path listed in the bundled rules; NetLog/hook shows it blocked, in normal and private windows. |
| S8 | No telemetry, crash uploads or new network destinations. Allowed: page loads, filter-list/uBOL updates, extension updates, Birch's updater, opt-in search suggestions (off by default), favicons (https only). | Code review rule; AGENTS.md 2.2 | With `BIRCH_HOME` set and only a local fixture server, record a NetLog for the whole run: every connection is to the fixture server. Chromium's Google services (Safe Browsing pings, component updater, variations, metrics, crash reporting, translate, spellcheck downloads, domain reliability, prefetch) must be off and shown off. |
| S9 | No page-to-app bridge: web content cannot call into the app. Injected scripts never paste page-controlled strings into script source; values are passed as arguments. | No WKScriptMessageHandler exists | No JS bindings/IPC handlers are reachable from web origins (Birch's own UI pages, if HTML, live on a scheme web pages can't navigate to or frame). Fixture page probes for any exposed object/handler; none. |
| S10 | The `chrome.runtime` page bridge for extensions goes only to exact hosts an installed extension lists in `externally_connectable`; wildcard host patterns are never honoured. | `ChromeCompat.exactHostPatterns`, `companionSites` | Engine-native `externally_connectable` is Chromium's; assert (fixture extension with a wildcard host) that a page on a matching subdomain can't message it unless the owner approves. |
| S11 | Opening another app (mailto:, zoommtg:, …) always asks first, except a clicked mailto/tel/sms/facetime link; grants last per site+scheme until quit; background tabs never prompt. | `openInOtherApp`; SORREL_SECTEST | Fixture page triggers a custom-scheme navigation without a click: hook logs a prompt (or refusal when hidden), and the OS handler was not invoked. |
| S12 | Main-frame `data:` navigations are blocked. | decidePolicyFor; SORREL_SECTEST | Fixture page sets `location = "data:text/html,…"`; the tab's committed URL is unchanged. |
| S13 | Downloads: quarantined/Mark-of-the-Web with the source address (private windows: without addresses); a download a page starts without a click asks once per site until quit (hidden tabs: blocked). | `quarantine`, SORREL_SECTEST2 | Download from the fixture server; check Zone.Identifier (Windows) / xattr (Linux, where applicable). Script-started download: prompt logged, file absent until allowed. |
| S14 | JavaScript dialogs and sign-in prompts from tabs not on screen are answered Cancel at once; from the second dialog a page can be silenced until it navigates. | `sheet(_:for:)`; SORREL_SECTEST2 | Hidden fixture tab calls `alert/confirm/prompt`; each returns immediately with the cancel value and no window appears. |
| S15 | A page that crashes its renderer more than twice within 60 s shows Birch's error page instead of reloading forever. | `webViewWebContentProcessDidTerminate` | Fixture that crashes the renderer (e.g. `chrome://crash` equivalent in a test-only build switch) three times; third time the error page shows. |
| S16 | Bundled pages are addressed `birch://<name>` with `<name>` matching `^[a-z0-9-]+$`; anything else (`../`, `/`) never loads a file. | `fixtures/state-derived.json` (bundled name cases); SORREL_SECTEST2 | Run those cases against the edition's bundled-page handler; `birch://../x` loads nothing. |
| S17 | Updates install only when the Ed25519 signature over the archive verifies against the built-in public key, the size and SHA-256 match, the build number is higher, and the bundle/edition/OS/arch match. Never weakened; never cross editions. | Updater.swift, SorrelUpdater; tools/update-test.sh | Agent 9's tests: tampered archive, wrong key, wrong edition, older build: all refused, old copy kept and reopened. |
| S18 | Extensions get only permissions their manifest requires at switch-on; optional ones are prompted; an update requiring more is held (extension off) until the person agrees. | `extensionApproved`; SORREL_EXTUPDATETEST | Local fixture extension v1 → v2 with an extra permission: v2 is held, logged, not active. |
| S19 | Tests never touch a real profile: every test run sets the profile root to a fresh scratch folder and keeps site data in memory; the shipping app refuses test hooks. | `Birch.app` refuses `SORREL_HOME`, drops `SORREL_*` | The release build ignores `BIRCH_*` hooks (unit test on the env filter); test builds refuse to start without `BIRCH_HOME`. |
| S20 | Chromium's sandbox is never disabled (by any command-line switch or setting) in any build, test or doc. | App Sandbox entitlements (Mac) | CI greps sources, CI files and docs for Chromium's sandbox-disabling switches (fails on any hit); runtime check of each child process's sandbox state (Chromium's sandbox status page) on Windows and Linux. |
