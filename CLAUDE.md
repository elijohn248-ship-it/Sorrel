# Sorrel

Sorrel (formerly Drift) is the owner's daily macOS browser: Arc-style Spaces and sidebar, Safari's engine (WebKit), Helium-style privacy, bangs, and Safari-style extensions with uBlock Origin Lite built in. It is a single-person project; there are no other users yet.

## Name, and the rename from Drift

The app was called **Drift** until 2026-11-14; it is now **Sorrel** ("Sorrel Browser"). The name was chosen after conflict checks: Flow, Breeze, Cove, Wren, Lagoon, Tern, Fern and Moss are already used by other browsers (many are new Arc replacements from Oct–Nov 2026, as Arc shuts down on 2026-12-22). `sorrelbrowser.com`, `sorrel-browser.com` and the GitHub names `sorrelbrowser`/`sorrel-browser` were free then; the US trademark search is still the owner's to do. The icon (redrawn 2026-11-14) is one solid deep-green sorrel leaf with a single cut-through midrib, leaning right on a quiet lavender -> sky -> mint tile; `tools/make-icon.swift` holds the design constants and also writes `Resources/logo.svg`, the vector master of the same mark.

Everything is renamed: bundle id `app.sorrel.browser`, `Sources/Sorrel`, the `Sorrel` SwiftPM target, `SORREL_*` test variables, `sorrel://` for bundled pages, the profile folder `~/Library/Application Support/Sorrel`, and the project folder `~/sorrel` (`~/drift` is a symlink to it so old references still resolve). The only deliberate "drift" left in code is a `drift://` -> `sorrel://` fallback in `Engine.load`.

**The Drift -> Sorrel copy** ran on the owner's first Sorrel launch (2026-11-14). Its code was replaced by the sandbox move below (it is in git history before the `sandbox` branch). **The Drift originals (`Application Support/Drift`, `WebKit/app.drift.browser`, `HTTPStorages/app.drift.browser*`) are the owner's backup: delete them only when the owner says so.**

## Sandbox

Sorrel runs in the macOS **App Sandbox** (`Resources/Sorrel.entitlements`, self-signed, hardened runtime). The point: a page or extension that compromised Sorrel's main process still couldn't read the owner's files, SSH keys, other apps' data, or run things freely. Inside it, Foundation's home folder (`NSHomeDirectory`, `homeDirectoryForCurrentUser`, `~/Library` lookups) is the container `~/Library/Containers/app.sorrel.browser/Data`; use `Sandbox.realHome` / `Sandbox.downloads` (Support.swift) when you mean the person's real folders. `Sandbox.isOn` tells you if it's active.

- **Entitlements, keep the list short:** network client; camera + microphone; location (websites that ask, added 2026-11-16 at the owner's request for Top Hat attendance); `~/Downloads` read-write; files the person picks in an Open panel (read-only: uploads, adding an extension); printing; and read-only temporary exceptions for `~/Applications` (Safari extensions, fallback browser) and the pre-sandbox data the move copies. Add an entitlement only when a feature is refused under the sandbox, and say why in the file.
- **Child processes inherit the sandbox but not access to picked files**: `ditto` unpacks a private copy of a picked zip (Extensions.add). `screencapture` from inside the app no longer works.
- **Signing and macOS permission prompts (2026-11-16):** a rebuilt app (new code hash) keeps opening its container without prompts, ad-hoc or self-signed (tested 2026-11-14 and 2026-11-16, including the switch from ad-hoc to self-signed). But **TCC permissions are stored against the designated requirement**, and an ad-hoc one is `cdhash H"…"`, new with every build. On macOS 27 the sandbox asks TCC before Sorrel touches `~/Downloads` even with the Downloads entitlement, so ad-hoc builds asked "access files in your Downloads folder" again after every rebuild and update (camera/microphone/location likewise). Hence the self-signed identity in Build and run. Watch TCC with `/usr/bin/log stream --level debug --predicate 'process == "tccd" OR process == "sandboxd"'`; launch the test build through `open -n --env …` for this, since a launch from a shell makes the terminal (VS Code) the responsible app.
- **Layout inside the container differs from outside** (found by experiment): WebKit keeps `Library/WebKit/WebsiteData`, `WebExtensions`, `ContentRuleLists` *without* the bundle-id folder, and the cookie jar is `Library/Cookies/Cookies.binarycookies`, not `HTTPStorages/<id>.binarycookies`.
- **The move (`Migration.swift`, first thing in `main.swift`).** On the first sandboxed launch (no `SORREL_HOME`; container has no `Application Support/Sorrel`; the real one exists) Sorrel COPIES, never moves: each item of `~/Library/WebKit/app.sorrel.browser/` -> `WebKit/<item>`, `HTTPStorages/app.sorrel.browser.binarycookies` -> `Cookies/Cookies.binarycookies`, `HTTPStorages/app.sorrel.browser/`, then `Application Support/Sorrel` (last; it marks the move done), via `.migrating` temp names; anything already in the way is set aside as `*.before-migration-<time>`. Then it merges the old preferences plist and writes `moved-into-sandbox.txt`. It refuses while an older Sorrel is running (offers to quit it), and on failure quits without keeping a partial copy, so the next launch retries. **The originals in `~/Library` stay as the owner's backup** and are what an unsandboxed build would still open. Verified end to end with the test build (cookie + open tab carried over). **The owner's real move ran on 2026-11-15** (`moved-into-sandbox.txt` in the container's profile), so the container is now the live profile. `SORREL_MIGRATE_TEST=<from Library>:<to Library>` runs just the copy between stand-in folders.
- **Window snapshots can't see page content under the sandbox**: `SORREL_SNAPSHOT` (cacheDisplay) shows the web area blank; the page is fine. Use `SORREL_WEBSNAPSHOT=<png>` for WebKit's own picture of the selected page.

## Non-negotiables

- **WebKit (WKWebView), never Chromium.** The owner values battery life and low upkeep. Don't propose Chromium, CEF or Electron.
- **Free to run.** No paid Apple developer account (the app is self-signed, or ad-hoc without the identity), no paid services. Phone sync, when it comes, is a PWA on Cloudflare's free tier.
- **Sites see this Mac's Safari.** The user agent's `Version/` is the installed Safari's own version (`Engine.safariVersion`), never the macOS version (they differ before macOS 26, and a too-low number triggers sites' outdated-browser warnings).
- **As private as Helium.** No telemetry. Ads and trackers blocked. Only two deliberate exceptions to "sites see Safari": the sites a Chrome-store extension lists under `externally_connectable` (e.g. Proton's sign-in pages) see a Chrome user agent and get a `chrome.runtime` bridge, because that's how they hand off to the extension.
- **Never touch the real profile from tests.** The real profile is in Sorrel's container (`~/Library/Containers/app.sorrel.browser`), with the pre-sandbox copy in `~/Library/Application Support/Sorrel`. Every test run uses **`build/SorrelTest.app`** (bundle id `app.sorrel.browser.test`: its own container, preferences and site data) and sets `SORREL_HOME` to a scratch folder under `/private/tmp` (see Testing). `Sorrel.app` refuses to start with `SORREL_HOME` set, and drops every other `SORREL_*` variable at launch (main.swift): test hooks work only in `SorrelTest.app`. With it set, cookies and site data also stay in memory (`Engine.store(for:)` returns one non-persistent store): WebKit files persistent site data by bundle id, not by profile folder, so before 2026-11-14 test runs were writing into the owner's real cookie jar. Keep it that way. Launching the app without `SORREL_HOME` is the owner's job, never an agent's.
- **Test windows must stay in the background.** The owner uses the Mac while work happens. Test runs (any run with `SORREL_SNAPSHOT` set) open behind other windows, take no focus and show no Dock icon. Keep that behaviour; `SORREL_LOUD=1` is the only override. Warn before anything that will take focus.
- **Don't loop on state only the owner can see.** Signed-in extension behaviour, hover feel, drag and drop: after one or two rounds, stop and give the owner a specific thing to try and what to paste back.

## Working in parallel (several agents at once)

The owner runs several Claude sessions at the same time. **Sessions must not share a working folder**: one session's half-finished edit breaks every other session's build (it happened twice on 2026-11-14).

- `~/sorrel` is `main` and the copy the owner runs (`build/Sorrel.app`). While other sessions are active, don't do feature work directly in it.
- Each task gets its own git worktree and branch: `cd ~/sorrel && git worktree add ../sorrel-<task> -b <task>` (or Claude Code's worktree option). Edit, build and test only there; each worktree has its own `.build/` and `build/`, and its first build takes a few minutes.
- Start every session with `git worktree list` and `git status` to see what's in flight.
- Before reporting a task done: commit on its branch, merge `main` into it, rebuild, and rerun the tests that cover what changed. Resolve conflicts in the worktree, never in `~/sorrel`.
- **The owner decides what merges.** Agents don't merge into `main` or push unless asked. `origin` (`github.com/elijohn248-ship-it/sorrel`) is **public**: anything pushed, this file included, is visible to everyone, so never commit keys, tokens or the owner's personal data (secrets live in `~/.config/sorrel`, outside the repo).
- Merged so far (2026-11-14/15): `sandbox`, `fluid-animations`, extensions work, `updater`. The `sandbox` worktree (`~/sorrel-sandbox`) is merged and can be removed when the owner says. When asked: `cd ~/sorrel && git merge <task> && ./build.sh`, then `git worktree remove ../sorrel-<task> && git branch -d <task>`, and tell the owner to quit and reopen Sorrel.
- Collision hotspots, so keep diffs there small and local: `App.swift` (every test hook; add a new hook as its own `if env[...]` block, don't reshuffle others), `Web.swift`, `SettingsWindow.swift`, `Support.swift` (each new setting needs a field AND a decoder line), and this file (edit only the section you're changing).
- Tests from different worktrees can run at the same time: each uses its own scratch `SORREL_HOME` and in-memory site data. Each test launch still opens a background window, so keep runs batched.

## Build and run

Only Command Line Tools are installed (no Xcode), so this is a SwiftPM build that `build.sh` wraps into an app bundle.

```
./build.sh            # release build -> build/Sorrel.app
./build.sh run        # build and open
./build.sh install    # build and copy to /Applications
open build/Sorrel.app  # open the current build
```

Minimum macOS is 15.4 (needed for `WKWebExtension`). The owner runs the build from `build/`; after a rebuild they must quit and reopen Sorrel to get it. Say so every time.

`Info.plist` sets `MallocSpaceEfficient=1` (see Memory). `main.swift` re-execs once with it if a launch lacks it.

Signing is **self-signed, with the hardened runtime and the App Sandbox** (`build.sh`: `--options runtime --entitlements Resources/Sorrel.entitlements`; see Sandbox). The identity is a free self-signed certificate in its own password-less keychain, `~/.config/sorrel/signing.keychain-db` (outside git; `SORREL_SIGNING_DIR` points elsewhere), made once by `tools/make-signing-identity.sh`. It makes the designated requirement `identifier "app.sorrel.browser" and certificate leaf = H"…"` for every build, so macOS permissions survive rebuilds and updates. Without it `build.sh` signs ad-hoc and says so. Losing it costs one more round of permission prompts, nothing else (the update key is separate). Gatekeeper treats it like ad-hoc (Open Anyway on first launch of a download). Each app also carries `Contents/XPCServices/SorrelUpdater.xpc` (the `SorrelUpdater` target, signed *without* the sandbox; see Updates). Every build makes two apps from one compile: `build/Sorrel.app` (the owner's) and `build/SorrelTest.app` (tests only; `build.sh` derives its Info.plist and entitlements from the real ones: bundle id `+.test`, display name Sorrel Test, no http/https handler, plus read-write on `/private/tmp/`). ATS uses `NSAllowsArbitraryLoadsInWebContent`: web pages may still load http://, but Sorrel's own requests (lists, updates, favicons, suggestions) must be HTTPS.

## How the pieces behave

- **Motion (`Motion`, Support.swift):** every slide, fade and pop uses the same three curves: `settle` (arriving), `leave` (going), `glide` (a state change). `Motion.run` wraps `NSAnimationContext`, `Motion.layer` wraps a `CATransaction`, `CALayer.popIn/popOut/press` move only the picture (never the model values), and `NSView.fade(in:)` replaces flipping `isHidden`. Reduce Motion drops movement and keeps fades. Sidebar rows and favorites keep their highlight in a layer so hover/selection crossfade; the outline slides single rows in and out (`reloadOutline` diffs the top level and falls back to `reloadData` for moves or folder changes). Add new animations through these helpers rather than ad-hoc durations.
- **Picture in Picture (`PictureInPicture.swift`):** View ▸ Picture in Picture (also a command-bar command) borrows the existing video tab’s WKWebView into a movable, resizable floating panel across Spaces. Hover reveals play/pause, ±10-second skip, return-to-tab, elapsed progress and approximate remaining time (Live when duration is unknown). A return button stays in the source pane. Fixed scripts in an isolated content world temporarily focus the video with reversible styles; the video node and stream stay in place. No new network requests, media URL extraction, persistent media state, or script message handler. Supports top-level and same-origin frame videos; cross-origin embeds and shadow-root players may require the site’s own PiP control. Closing/navigating the source dismisses PiP; even paused PiP tabs resist sleeping. Private pages retain their non-persistent store. Real mouse dragging/hover feel and signed-in streaming sites need owner checks.
- **Sidebar mini player (`MediaPlayer.swift`):** a compact card above the space icons appears for playing media in normal sidebar tabs and remains available while paused or muted, across tab/space switches. Track details sit above 15-second rewind, play/pause and forward controls; native tab-wide mute sits by the title. No source dropdown: newly playing tabs take over automatically, with a playing source preferred over paused tabs; clicking the card returns to its tab. Seeking uses fixed JavaScript with the offset passed as an argument, targets previously played media in the main document or same-origin frames, preserves pause state, and clamps to seekable ranges. Cross-origin frame players and unseekable streams show a return-to-tab hint instead. Uses native WebKit playback state, metadata and runtime-checked private media selectors; audio-only resume verifies native playback then falls back to a fixed script for a previously played element (same-origin frames included). No page-to-app bridge, fetched artwork, saved media state, or private-window sources. Polls loaded tabs once per second; muted playback protects a tab from sleeping. The Library suppresses the card; downloads and updates stack above it. Site-specific media handlers and the feel still need owner testing.
- **Multiple normal windows:** File ▸ New Window (⌘N, `window.new`), Close Window (⇧⌘W). Each `MainWindowController` has a `Store` session with its own current space and per-space selection. `Store.profile` owns shared sidebar data, archive and the single save debouncer; `Store.shared` resolves the last focused normal window for commands. Views and source-page callbacks use their owning window's store. Selecting a tab or split pane already visible in another window focuses that window; a page is never mounted twice. All windows' visible panes are protected from sleep/archive. Normal windows share existing WebKit login stores; private mini windows remain separate and are never restored. Optional `AppState.windows` stores normal window IDs and selections, with legacy fields retained for old saves. Quit preserves the complete snapshot while AppKit closes windows. Extensions have one adapter per normal window, with matching active tabs and popup anchors; private window requests from extensions are refused.
- **Sidebar hover:** `MainWindowController` modes `pinned` / `hidden` / `peeking`. Reveal strip width, overshoot reach, hide delay and slide speed are all in `settings.json` and Settings ▸ Sidebar. While peeking, a 40 ms timer watches the real cursor (events stop arriving once it leaves the window; plain timers pause during menus/drags, which is wanted).
- **Command bar:** ⌘T = centered bar. ⌘L and clicking the address box = in-place editor anchored on the pill. A `focusHolder` on `SorrelWindow` stops pages stealing focus while the bar is open. The bar's top edge never moves; while typing, rows are diffed by `Result.key` (kept rows update in place, others fade in/out, never `reloadData`), the last suggestions that still prefix-match stay up until the new ones arrive, and the list height follows a critically damped spring on the view's display link (`setListHeight`), so blur, border and shadow move together and a new keystroke just retargets it.
- **Peek (link preview):** any clicked link to a different site opens over the page; ⌘O expands, Esc closes. Excluded on search engines (`peekExcludedSites`) and off for script-opened windows (sign-in pop-ups must still work).
- **Split view:** a split is an `Item` with `split: SplitLayout` (stacked flag + pane fractions) and 2–4 tabs in `children`, so it moves, pins, archives and saves as one unit, shown as one sidebar row. `Space.selectedID` is the *focused pane*, so the address box, ⌘L, ⌘W, find and extensions all act on it. Clicking into a pane focuses it (local mouse-down monitor). Closing a pane of an unpinned split closes that tab; in a pinned split it sleeps. One tab left = the split dissolves. Favorites can't be in a split. Store API: `makeSplit`, `removeFromSplit`, `unsplit`, `split(containing:)`, `unit(_:)`. Ways in: ⌃⇧= (command bar opens a pick beside the current tab), right-click a tab ▸ Open in Split View, drag a tab onto the page's left/right/top/bottom, drop a tab on a split row, or the split button on Peek. ⌃⇧- separates, ⌃⇧] / ⌃⇧[ move focus.
- **Row button (`TabActionButton`, Sidebar.swift):** pinned tabs and pinned split rows show "−" on hover while loaded (unload = `Store.close`, which sleeps them), then the two strokes rotate into "×", which runs `Store.closeAndUnpin` (out of the sidebar; ⌘⇧T reopens each tab unpinned). Clicks within 0.35 s of the change are ignored so a double-click can't remove the tab. Unpinned tabs show "×" as before. The strokes sit in one group layer so their transparency isn't doubled where they overlap.
- **Space swipe (`SpaceSwipe.swift`, 2026-11-16):** a sideways two-finger swipe anywhere over the sidebar (the tab list's `SidebarScroll.onScroll` and `SidebarView.scrollWheel` both feed `SpaceSwipeTracker`), or click-and-hold on the space icons and drag (`SpaceStrip`; the buttons forward their mouse events, so a plain click still picks and right-click still shows the menu), slides between spaces. `SpacePager` keeps a position in spaces: the live page (`spaceContainer`, inside the clipping `spaceClip`, moved by the `spaceOffset` constraint) sits where the current space belongs, other spaces in view are `SpacePreviewView`s (same cells, no clicks or hover, each in its own space's light/dark look), the window and floating sidebar gradients blend (`ThemeBackgroundView.blend`), and the space-bar tint slides between icons (`SpaceBar.show(position:)`). Fingers drive it directly (the page follows the fingers whatever the scroll direction setting; past the ends it rubber-bands to at most half a page); scrubbing follows the cursor on a quick spring. On let-go the store switches at once (so the web page and colours change while it lands) and a critically damped spring settles it; a flick faster than 0.6 spaces/s goes on to the next space, otherwise it lands on the nearest. A swipe's momentum glide is swallowed; wheel mice, vertical scrolls and an open Library are left alone. The usual push transition is skipped while the pager is active. Feel is the owner's to judge. **Many spaces:** the icons sit in `SpaceRowScroll`, a sideways-scrolling row between the left buttons and +; it stays centred under the bar while the icons fit; **every scroll over the icons is the row's and never switches spaces** (owner's request, 2026-11-16): two fingers sideways or up/down, momentum included, or a wheel mouse slide the row (nothing happens while they all fit), the ends fade where icons are hidden, the current space's icon is scrolled into view on every switch (and follows a trackpad swipe), and while scrubbing, resting the cursor in the last 24 pt at either end keeps the row scrolling (a 60 Hz timer in common run-loop mode, so it runs during mouse tracking).
- **Download flight and progress (2026-11-16, `DownloadFlight.swift`):** when a page in the main window starts a download, `Engine.onDownloadStarted` hands it to `MainWindowController.downloadStarted`: the file-type icon lifts at the last click (a local mouse-down monitor; else the page's centre), arcs with a halo in the space's colours and a three-ghost trail, and drops into the Library button, which squashes and sends out two ripples (`DownloadsButton.catchLanding`). With the sidebar hidden it lands in `DownloadsCapsule` (bottom left of the page, the space's gradient, its own `DownloadsStrip`). While in the air the record is in `DownloadFlight.inFlight`, which the strip and the ring leave out, so the row rises in as the icon lands. Bars are `Theme.progressColors` (the space's colours, lifted on dark / deepened on light, system accent for grey spaces) with a glow, a sweeping light while downloading and a gliding segment when the size is unknown. Strip rows (`showsCompletion`) stay 2.6 s after finishing (full bar, a tick that draws itself) or 1.6 s after failing/cancelling, then fade. Downloads shown this way get no Downloading/Downloaded toasts (`DownloadRecord.shownInWindow`); mini/private windows still toast. Reduce Motion: no flight, rows fade in. Feel is the owner's to judge.
- **Space colours, Arc-style (`ThemeLook.swift`, branch `arc-colors`, 2026-11-16):** every colour goes through OKLab. `Theme.soften` eases a colour's chroma through a soft knee (vivid -> pastel, gentle unchanged), in dark mode sinks its lightness to a deep tone (`min(L, 0.3 + 0.2L)`; Arc turns coral into rust), then mixes toward the light/dark base by the strength. `gradientStops` gives 16 stops on a half-linear/half-smoothstep curve (one colour gets a faint ±0.025 lightness lift); every theme has the same count, so a space swipe blends stop by stop (`Theme.blendedStops`). `resolvedColors`/`isDark` use the softened colours. **Grain** (`Theme.grain`, 0…1, optional so old saves load; nil = `Theme.defaultGrain` 0.35; Arc's `noiseFactor` imports into it) is a sublayer of `ThemeBackgroundView` filled with a 128 pt pattern tile of light and dark specks (one per Retina pixel), opacity `grain × Grain.strength` (0.32), hidden at 0. Customize Space has Arc's palette as presets, a colour wheel (hue round, vividness out, drawn softened with grain; dragging the first dot turns the others with it, others move alone, a dot keeps its colour's brightness; a click off the dots moves the first), the exact colour wells beside it, and a Grain slider. Adding a colour starts it opposite the first (then a third of the way round). Old spaces keep their own colours but now draw softened; presets changed (new spaces only). **Optional brightness (2026-11-17):** Customize Space has a Brightness slider. `Theme.brightness` is optional (nil = 0, keeping old saves unchanged); `brightnessAmount` clamps to 0…1. After softening/dark-mode dimming, `soften` blends back toward the original OKLab colour by brightness, before applying strength. At 1 the original colours retain their vividness and dark-mode lightness; foreground appearance still follows `isDark`. The wheel and preset swatches preview brightness live; selecting a preset keeps it. Grain, gradients and swipe blending use the same path. Feel is the owner's to judge.

- **ChromeCompat:** adds inert stand-ins for Chrome-only APIs (`runtime.onUpdateAvailable`, `offscreen`, `idle`, …), a `requestIdleCallback` polyfill (and a private copy inside page-world scripts that need it), and **pins `globalThis.chrome`/`browser`** because Proton Pass replaces them with a locked Proxy and WebKit then silently drops every message. It only ever *adds*; **never wrap or Proxy the extension API, and never reassign `sendMessage`/`addListener`, even for tracing: delivery stops.** Bump `ChromeCompat.version` when you change it so installed copies re-patch (13 since 2026-11-15: wildcard `externally_connectable` hosts dropped from the bridge; 14: Chrome-only event listeners guarded, below). **Guarded Chrome-only events (`guardChromeOnlyEvents`, v14):** the extension's own .js files get `x.onUpdateAvailable.addListener(` rewritten to `x.onUpdateAvailable?.addListener(` (same for the other Chrome-only events in `chromeOnlyEvents`), because on some background restarts WebKit hands the worker fresh `runtime`/`webRequest` objects without the shim's stand-ins. - **Wake before pop-up (`Extensions.wakeBackground`):** WebKit unloads an idle extension's background after 30 s. If opening a pop-up is what restarts a *service worker* background (Proton Pass), WebKit starts the worker in the pop-up's own process, reports "Background content loaded" before the worker's install step, then disables it ~6 ms later: the pop-up never gets an answer and stays an empty 50×50 box with no URL (found 2026-11-15 from WebKit's `com.apple.WebKit` log). So clicking an icon, or its `_execute_action` shortcut, first calls `loadBackgroundContent`; if that took >30 ms (it had stopped) the pop-up opens 0.3 s later (0.1 s already passed in tests; 0 s failed), otherwise at once. Background-*page* extensions (uBOL) never had the problem. Repro: `SORREL_EXTTEST=ui SORREL_UI_EXT=chrome-ghmb SORREL_UI_PREWAIT=40`. **Extension pages in tabs get the same wake-up** (`Engine` navigation policy -> `Extensions.wakeBackground(beforeLoading:)`, holding the decision until the background is up): when Proton's settings page (or a restored / re-woken Proton tab) was what restarted the stopped worker, its background ran without the compat stand-ins (`runtime.onUpdateAvailable` undefined at background.js:62, though `chrome.offscreen` survived) and crashed, leaving every later pop-up empty (found 2026-11-15; reproduced 10/10 before, 0 after). Keeping references to the patched objects, or putting stand-ins on the prototype, did NOT help; diagnostic code in the loader sometimes hid the crash, so test with the real loader. Ordinary web pages' content scripts waking it were always fine. `run` fires exactly once, with a 2 s fallback, because WebKit sometimes never answers `loadBackgroundContent` after a failed start. Repro of the page path: same as above without `SORREL_UI_NODASH`, on a fresh profile (profiles restore their tabs, so reused ones pile up extension tabs and muddy results).
- **Pop-up sizing:** WebKit sizes action pop-ups to content; Chrome pop-ups that declare a fixed size (Proton: 600×430) collapse to a strip. `applyDeclaredSize` reads the size from the extension's stylesheet (not the live page) and sets `width/height` plus `min-width/min-height` on html and body so WebKit's popover grows. **Minimums alone are not enough** (2026-11-16): Proton's `height: 100%` chain resolves against the real `height`, so with only `min-height` its app area shrank to its header (600x115) and the signed-in item list and details got 0 height.
- **Pop-up speed (2026-11-16):** (1) hovering an extension's icon calls `Extensions.prewarm`, which wakes its background, so the click usually finds it running and skips the cold-start wait (~0.45 s for Proton); `wakeBackground` remembers when it last restarted one (`restartedAt`) and waits out only the rest of the 0.3 s settling time. (2) `presentActionPopup` sizes the page *before* showing the popover: it waits for the web view's `intrinsicContentSize` to reach the declared size (~20 ms), then 80 ms more (WebKit hands the size to its popover after a delay of its own; shown sooner, it opened at 356x338 and jumped; 60 ms measured enough), with a 0.3 s fallback. Setting `popover.contentSize` or the view's frame by hand did NOT stick. (3) `applyDeclaredSize` adds a constructed stylesheet making `.anime-fade-in` 0.12 s with no delay (Proton's nested fade-ins read as a ~0.6 s fade). Measured warm, click to fully drawn: ~0.82 s -> ~0.42 s; cold with a hover first, about the same as warm. Test with `SORREL_UI_HOVER=<ms>` (pre-wake that long before the click). Hosting `popupWebView` in our own popover does not work (WebKit keeps resizing it).
- **Pop-ups never count as hidden (`keepPopupAwake`, 2026-11-16):** WebKit treats a page as hidden when macOS reports its window occluded, even a shown popover; a hidden page gets no animation frames and its CSS animations freeze at frame 0. This was a suspected cause of the owner's blank Proton list but turned out not to be (see Pop-up sizing); it does keep pop-ups drawing when covered, and makes them render in background test windows. The pop-up web view gets WebKit's `_setWindowOcclusionDetectionEnabled:` set to NO (called directly; KVC `setValue(_:forKey:)` throws). Tabs keep occlusion detection. The `ui` test hook logs `ui: popup frames visibility=… rAF=…`; with this, pop-up screenshots in background test windows are no longer blank.

- **Browser import (`Importer.swift`, `ImportView.swift`; File ▸ Import from Another Browser…, Settings ▸ General, command `import.browser`):** the sandbox forbids reading other apps' data, so each import goes through an Open panel already pointed at the browser's folder (`com.apple.security.files.user-selected.read-only`, no new entitlement); the person clicks Allow. Arc: `StorableSidebar.json` gives spaces (name, emoji, colour: a near-white colour falls back to `primaryColorPalette.midTone`; a gradient keeps its base colours), pinned tabs, folders (`list`), splits (`splitView`), unpinned tabs and favorites (`topAppsContainerIDs`); spaces on a non-default Arc profile get separate logins; history comes from `User Data/<profile>/History`. Chromium browsers: `Bookmarks` JSON per profile (several profiles -> a folder each) + `History`. Firefox/Zen: the install-default profile's `places.sqlite` (bookmarks + history; Zen's workspaces/pinned tabs live in a compressed session file and are NOT read). Safari: `Bookmarks.plist` + `History.db`; if macOS keeps that folder private, the card says to export bookmarks as HTML. Any browser's exported bookmarks HTML works too. Databases are copied (with `-wal`/`-journal`) to a temp folder in the container, read, and deleted, since running browsers lock them. Only http(s) addresses; history capped at the newest 10,000 per import. Bookmarks become pinned tabs in a space named after the browser. Merging: a space with the same name is filled in, same-named folders merge, and a page already in that space (or already a favorite) is skipped, so importing twice adds nothing. Cookies and passwords are never read. Motion: the card hangs from a fixed line and grows downward, steps slide by direction, the chosen browser icon flies into the header, rows rise in sequence, errors shake the card, the done ring draws itself and the wash takes the new space's colours.

- **Security behaviour (keep it):** HTTPS-first (`httpsFirst`, on by default): main-frame http:// GETs to ordinary hosts are retried as https://; if that fails or bounces back to http://, `showInsecureWarning` shows Sorrel's own page, and its Continue button (`sorrel-insecure:continue`, honoured only while that warning is up in that web view) allows the host until quit. Local names, IPs and non-80 ports are never upgraded. Sorrel's own error/warning pages go through `loadInternalPage` so navigation policy lets them through. Pages opening other apps (`openInOtherApp`) ask first, except clicked mailto/tel/sms/facetime links; grants last until quit. Main-frame `data:` navigations are blocked. Downloads are quarantined (WebKit does it; Sorrel drops the source addresses for private windows). ⌘/middle-click from a private window opens another private window, never a normal tab. Camera/mic choices are keyed by asker + top site, and never remembered in private windows. **Website location (2026-11-16, `Engine.askForLocation`):** off by default; every request shows a sheet ("Don’t Allow" is the default button), nothing is remembered (WebKit keeps a yes only for that page until it reloads or navigates), hidden tabs are refused. WebKit asks through the private `WKUIDelegatePrivate` methods `_webView:requestGeolocationPermissionForOrigin:initiatedByFrame:decisionHandler:` (and the older `…ForFrame:` spelling); without them every page was silently refused. WebKit holds a hidden page's question until it shows, so background test windows never reach the prompt. After a yes, a toast points to System Settings if macOS keeps location from Sorrel. **Web Bluetooth does not exist in WebKit** (`navigator.bluetooth` is undefined, Safari too), so there is no Bluetooth prompt to add; a bridge would need the page-to-app JS bridge rule 4 forbids. Favicon fetches are https only and carry the page's user agent. Extensions get only manifest-required permissions on switch-on; optional ones go through the prompt delegates and approvals persist in `settings.json` `extensionGrants`. What a manifest required at switch-on is recorded in `extensionApproved`; an update (Chrome Web Store or uBOL) that requires more is held back with the extension off until the person agrees (tests never ask: they log `ext: … held back`). Added 2026-11-15 (security audit): the address box drops only a *leading* `www.` (`Site.display`), cuts long hosts at the front so the real domain stays visible, and shows an orange open lock on http:// pages; JS dialogs and sign-in prompts from tabs that aren't on screen are answered "Cancel" at once (never an app-modal dialog), and from a page's second dialog on there is "Don't let this page show more dialogs" (until it navigates); the not-secure Continue works only while that warning is the page showing; downloads a page starts without a click (`WKDownload.isUserInitiated` false) ask once per site until quit (hidden tabs and tests: blocked, toast); `sorrel://` names must be `[a-z0-9-]+`; a page that crashes its web process more than twice a minute gets the error page instead of endless reloads.

## Updates

Sorrel updates itself from the owner's GitHub releases, free and without Apple: **`UpdateConfig.repository`** (`Sources/SorrelUpdateCore/UpdateCore.swift`, currently `elijohn248-ship-it/sorrel`, which is `origin`) and the feed `https://github.com/<repo>/releases/latest/download/updates.json`, which GitHub redirects to the newest published release's asset. Built 2026-11-15 and merged into `main`; `main` was first pushed to that repository on 2026-11-15. **First release: 0.2.0 (build 2), published 2026-11-16** (tag `v0.2.0`). Cut releases in a worktree, not `~/sorrel` (`build.sh` deletes the owner's running `build/Sorrel.app`), then fast-forward `main` to the release commit so the next build number goes up. The GitHub repo is now named `Sorrel` (capital S); GitHub redirects the lowercase name, and the feed works through it.

- **Releasing:** `tools/release.sh 0.2.0` bumps `CFBundleShortVersionString` to 0.2.0 and `CFBundleVersion` by one (the build number is the only thing compared, so it must only ever go up), builds, zips `build/Sorrel.app` (`ditto --keepParent`), signs the zip, writes `dist/` (zip, `updates.json`, `notes.md`, `release.env`), commits "Sorrel 0.2.0 (build N)" and tags `v0.2.0`. Nothing leaves the Mac until **`tools/release.sh publish`**: push, GitHub release with both assets (via `gh`, or `GITHUB_TOKEN` / `~/.config/sorrel/github-token` through the REST API; neither `gh` nor Homebrew is installed, and the token file exists, so the REST path is the one in use), then it polls the feed. Cutting is an agent's job when asked; **publishing is the owner's go-ahead** (it reaches every installed copy).
- **Signing key:** Ed25519 via CryptoKit, `tools/update-sign.swift`. The private key is `~/.config/sorrel/update-signing-key` (mode 600, never in git); its public half is `UpdateConfig.publicKey`. **If the private key is lost, no installed copy can ever accept another update** (they'd all need a fresh download): the owner should keep a copy in their password manager. `release.sh` refuses to cut with a key that doesn't match the built-in public key.
- **In the app (`Updater.swift`):** 30 s after launch and every 30 min it checks whether 6 h have passed (`Updates/last-check`), gated by the `checkForUpdates` setting (Settings ▸ General ▸ Updates, with version, Check Now / Relaunch to Update, status); Sorrel ▸ Check for Updates… (`updates.check`) checks at once. A newer `build` is downloaded to `Updates/Sorrel-<build>.zip` (ephemeral session, no identifying request), checked against size, sha256 and the Ed25519 signature; a failed check deletes it and says so. A verified zip is "ready": the sidebar card appears (below) and the menu item becomes "Relaunch to Update to X…", and **it installs when Sorrel quits** (`applicationShouldTerminate` returns `terminateLater` until the service has it) or at once from the card / the menu / the Settings button.
- **The sidebar card (`UpdateCard.swift`, 2026-11-16, owner's request: Arc's updater without its habit of reappearing after "update and restart", which left people unsure it had worked).** It sits between the downloads strip and the space bar, takes no room when hidden, steps aside while the Library is open, and only ever shows `Updater.card`, which is worked out from the updater's real state: `ready` ("Sorrel X is ready", **Update and Restart**, ☐ **Update automatically**, ×) -> `updating` (spinner, at once on click; Sorrel quits) -> at the next launch `updated` ("Updated to Sorrel X", goes by itself after 6 s *on screen*: not while the sidebar is hidden) or `failed` ("Update didn't install" + the installer's reason from `update.log` (`Updater.lastAttempt`) + **Try Again**, which reuses a ready zip or fetches a fresh one and installs at once) -> after two failures of the same build (`Updates/failed-installs`) `gaveUp` ("couldn't install", **Open Download Page** = the GitHub release in a new tab) and install-on-quit stops trying that build; a newer build in the feed clears all of that. **The launch after an install decides from what is running**: the `installing` marker holds "<build>\n<version>"; equal to the running build = updated, newer = failed (its zip is deleted so a retry downloads afresh), unless the log shows the installer still at work (<2 min, no ending), in which case the marker is kept for the next launch. A failure is never turned back into a plain "ready" card in the session that reports it. × hides the card until the next launch (a ready update still installs on quit). **Update automatically** (`installUpdatesAutomatically`, off by default; also Settings ▸ General ▸ "Install updates automatically, without asking"): ready updates show no card and install quietly on quit; ticked on a card, that card stays for its own update (`keepCardFor`). The old "ready" and "updated" toasts are gone; a manual Check for Updates still asks with an alert. The feed and zip requests are the only network traffic; nothing about the person or Mac is sent.
- **Installing (`SorrelUpdater.xpc`, unsandboxed on purpose):** the sandboxed app can't write to /Applications, and children inherit the sandbox, so the swap is done by an XPC service launchd starts for the app (`Contents/XPCServices/SorrelUpdater.xpc`, bundle id = app id + `.updater`, built from `Sources/SorrelUpdater`, ad-hoc + hardened runtime, **no entitlements**). It treats everything the app sends as hostile (security audit, 2026-11-15): it installs only over **the bundle that contains it** (three levels up from the .xpc; the app no longer names a path), checks that bundle's id equals its own minus `.updater`, **reads the zip once, verifies those bytes in memory and keeps a private copy in `~/Library/Caches/<service id>/`** (out of the sandbox's reach, so the app can't swap the file after the check; the installer accepts only such a copy and deletes it afterwards), and **takes no paths from the app: the zip and `update.log` arrive as files the app opened itself** (`FileHandle`s over XPC; the log must be a plain file of this user's with one link, control characters stripped). Why (2026-11-16): **macOS's app-data protection (TCC `kTCCServiceSystemPolicyAppDataDetailed`) refuses the service any path inside the app's container**, even as the app's own XPC service, so the earlier path-based design refused every real install (the zip and log both live in the container; tests passed only because `SORREL_HOME` puts them under /private/tmp). An open file also means the service can only write where the sandboxed app itself could. **Copies on 0.2.0–0.2.2 carry the old service and most likely can't update themselves; they need one manual download.** Note: launchd starts the service with some of the app's environment (Foundation's home folder there is the app's container, so the service uses `getpwuid` for the real home) but **not the app's own variables** (`SORREL_*` don't arrive). Then it `posix_spawn`s itself as a detached installer (`POSIX_SPAWN_SETSID`, because launchd ends the service with the app) which waits for the app's pid to exit, `ditto -x -k`s the zip beside the app (or inside the bundle, swapping `Contents`, if the folder isn't writable), refuses a bundle with another id or a build that isn't newer, runs `codesign --verify --deep --strict`, strips `com.apple.quarantine` from every file (otherwise Gatekeeper would refuse the ad-hoc app), swaps with two renames, and `open`s the app if asked. **With relaunch, it reopens the app even when the install failed** (after waiting for it to quit), so the person is never left without their browser and the old copy can say what happened. For a test build logging under /private/tmp the service passes relaunch "2" and the installer logs `reopen skipped in a test` instead of opening a focus-taking window. Everything is logged to `Updates/update.log`. Verified 2026-11-15 with `tools/update-test.sh` both under /private/tmp and in /Applications (no App Management prompt appeared for this admin account).
- **Known limits:** an app run straight from Downloads is translocated (`/AppTranslocation/`); Sorrel then explains to move it to Applications instead of trying. Releases are signed with the self-signed identity, so permission grants survive updates (an ad-hoc build would be asked again). First launch of a downloaded copy still needs System Settings ▸ Privacy & Security ▸ Open Anyway (no notarization); the release notes template says so. There is no key rotation: changing the key means every user downloads afresh. Downgrades are refused everywhere (a feed pointing at an older build does nothing).
- **Testing:** `SORREL_UPDATETEST=version|check|install|quit` with `SORREL_UPDATE_FEED=file:///…/updates.json` (honoured only by the test build): `version` logs what is running and quits, `check` finds/downloads/verifies and quits without installing, `install` is the Relaunch to Update path (relaunch off in tests, so no window takes focus), `quit` is install on quit. `badlog` (a pipe, a folder and a hard-linked file as the log: each must be refused), `swapzip` (overwrites the zip right after the handoff and tries to reach the service's private copy; the checked bytes must still install; logs inside the test app's container like the real app) and `containerlog` (prints that container log) cover the audit fixes. `card` / `relaunch` / `retry` drive the sidebar card through its real buttons and log `updater: card:` lines (`SORREL_CARDSHOTS=<dir>` + `SORREL_CARDSTEP=<name>` write pictures). `tools/update-test.sh [folder]` does the whole thing with throwaway copies of `SorrelTest.app` and fake newer builds signed with the real key (two of them "broken": signed archives whose app fails `codesign --verify`, for the failure cards); pass `/Applications` to test the real location (it removes `SorrelTest.app` from there afterwards). Output lines start with `updater:`. Quiet test runs never check for updates unless `SORREL_UPDATETEST` is set.

## Memory

Measure with `footprint -p <pid>`, not resident size: WebKit leaves 1 GB+ of reclaimable pages that `ps` counts. With uBOL on, the main process was ~235 MB of true footprint from malloc fragmentation after rule loading; `MallocSpaceEfficient=1` brings it to ~45 MB. Things that did not help: `malloc_zone_pressure_relief`, `MallocAggressiveMadvise`, trimming uBOL's unused rule sets.

## Testing

There is no test target. Tests are the app itself, driven by environment variables read in `App.swift` (`runDebugHooks`). Pattern:

```
S=$(mktemp -d /private/tmp/sorrel-test.XXXXXX); mkdir $S/p1
SORREL_HOME=$S/p1 SORREL_SNAPSHOT=$S/shot.png SORREL_DELAY=8 SORREL_OPEN=https://example.com build/SorrelTest.app/Contents/MacOS/Sorrel 2>&1 | grep -E '^(selected|hover|peek|ext|ui|diag|autofill):?'
```

`SORREL_WINDOWTEST=1` (multi-window creation, independent tab/space selections, shared normal login store and isolated private store, source-window background links, focus-existing behavior, split panes, sleep/archive protection, extension ownership, closing/reopening and saving; logs `windows:` expected/got booleans; `SORREL_DELAY=8`). `SORREL_WINDOWTEST=restore` checks two saved windows after relaunch: copy the generated scratch `state.json` into a **fresh** scratch profile, never reuse a running profile. Normal quit must leave both window snapshots on disk.

`SORREL_BRIGHTNESSTEST=<existing scratch directory>` (`SORREL_DELAY=8`): legacy soft defaults, full-brightness colour endpoints in light/dark, valid gradients for all presets, swipe endpoints, the actual slider and preset actions, wheel/grain preservation, isolation from another space, state-file roundtrip, reopening the editor and returning to soft. Writes `brightness.png`; logs `bright:` expected/got checks. Run separately from `SORREL_THEMETEST` and `SORREL_SWIPETEST`.

`SORREL_PIPTEST=<local mp4 path>` (`SORREL_DELAY=25`, optional `SORREL_PIPSHOT=<png>`: silent local video, viewport sizing, native hover button hit testing, pause, ±10 seconds, clamping, remaining time, tab switching/return, same-origin frame, navigation/close and private-store teardown; logs `pip:`. Generate a fixture with `swift tools/pip-fixture.swift /private/tmp/<fresh folder>/video.mp4`; use a fresh test profile as usual).

`SORREL_MEDIATEST=1` (silent local WAVs: detection, pause/resume, mute/unmute, muted-tab sleep protection, tab/space switching, Library suppression, automatic handoff between multiple sources, closing, navigation and private-store isolation; `SORREL_DELAY=25`, optional `SORREL_MEDIASHOT=<png>` captures the window with the player; logs `media:`).

`SORREL_MEDIASEEKTEST=1` together with `SORREL_MEDIATEST=1` checks the real forward/rewind button actions while paused and clamping at both ends of the silent fixture; logs `seek:` expected/got booleans.

## Polish phase: rules and workflow

Sorrel is basically built. The job now is fixing bugs and hardening it into a complete, private, secure browser. Prefer small, verified changes over rewrites.

### Hard rules
1. **Never weaken a security or privacy setting to fix a bug.** If a site breaks because of blocking, the sandbox, or a permission prompt, add a narrow per-site exception or ask me. Why: a privacy browser that leaks once isn't private.
2. **No new outbound network calls** beyond what exists (page loads, filter-list updates, the updater). No analytics, crash reporting, or telemetry, ever. Why: privacy is the product.
3. **No new entitlements or temporary exceptions.** Resources/Sorrel.entitlements should only shrink. Ask before touching it.
4. **No page-to-app JavaScript bridge.** There are no WKScriptMessageHandlers today; keep it that way unless I approve one. Scripts the app injects never paste page-controlled strings into JavaScript source; pass values as arguments (callAsyncJavaScript arguments:) instead.
5. **Every bug fix gets verified** (see Bug workflow), and the build must pass before you say you're done.
6. **Don't add warnings.** The release build has 9 known warnings (self-capture in closures). Keep it at 9 or fewer.
7. **Don't hand-edit vendor/.** It's third-party code (uBlock Origin Lite, Kagi bangs); update it by replacing it from upstream.
8. **Don't run ./build.sh in ~/sorrel without asking.** Its first step deletes build/Sorrel.app, the copy the owner runs, which is usually open. In a task worktree it's fine: that's how build/SorrelTest.app gets rebuilt for tests. Use `swift build` to check that things compile.

### Security invariants (re-check whenever you touch related code)
- Private windows always use a non-persistent WKWebsiteDataStore (Web.swift: makeConfiguration, store(for:)), never the default store. Private downloads, history, and session restore leave nothing on disk after the window closes.
- Never auto-grant a permission. Camera/mic in private windows ask every time (Web.swift ~656-668).
- The `sorrel-insecure:` link works only from Sorrel's own warning page. A web page must not be able to link to it to skip the warning.
- ChromeCompat's chrome.runtime page bridge goes only to the sites a Chrome-store extension lists under `externally_connectable` (Extensions.swift: `companionSites`; today just Proton Pass's `account.proton.me` and `pass.proton.me`). Don't widen that, and ask before an extension whose list uses wildcard hosts gets it. In code, `ChromeCompat.exactHostPatterns` leaves wildcard-host patterns out of both the Chrome identity and the bridge (WebKit's own `browser.runtime` for those pages is unaffected).
- openInOtherApp always asks before launching another app. File uploads reach only files the user picked.
- The URL bar always shows the real origin of the page; lookalike international domains display as punycode.
- Content blocking stays on by default. A broken site gets a per-site toggle, never a global off switch.
- The updater installs only updates whose signature verifies. Never weaken that check. SorrelUpdater is deliberately signed without the app's entitlements; keep it that way.

### Commands
- Fast compile check: `swift build` (debug). Release compile: `swift build -c release`.
- Package: `./build.sh` (ask first in ~/sorrel, rule 8). Updater test: `tools/update-test.sh`.
- Only Command Line Tools are installed, not Xcode: don't use xcodebuild.
- Manual tests: run build/SorrelTest.app with the env-var hooks in the Testing section. Use a fresh folder per run (`mktemp -d /private/tmp/sorrel-test.XXXXXX`; the sandboxed test build can only write under /private/tmp) rather than deleting old ones.

### Bug workflow
1. Take the bug from BUGS.md (create it if missing: repro steps, expected, actual).
2. Reproduce it first, using the SorrelTest.app hooks (e.g. SORREL_SNAPSHOT) or a written repro. Say so if you can't.
3. Fix the root cause with the smallest change that works.
4. Verify: the build passes, the repro now behaves correctly, and nearby features still work.
5. Mark it fixed in BUGS.md with a one-line cause, and put anything unfinished in PROGRESS.md.
One bug per session where possible.

### Hooks (.claude/)
- A Stop hook compiles the project when Swift files have changed. If it reports errors, fix them.
- A security hook flags risky patterns in your edits. When it fires, check the change against the invariants above, and list every flagged item in your final summary so I can review it.
